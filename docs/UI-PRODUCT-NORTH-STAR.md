# UI Product North Star

MDx should feel like one coherent workspace, not a collection of system dashboards.

## The product idea

People come to MDx to think, build, write, coordinate, and make decisions with AI while retaining authority over consequential actions.

- Twin is the conversational home for grounded work.
- Forge takes on scoped software jobs and returns inspectable work.
- Pages turns drafts and sources into durable knowledge.
- Message carries team conversation and system handoffs.

These are different rooms in one workspace. They should share navigation, typography, interaction patterns, and a consistent stance toward evidence and approval.

## Experience principles

1. Start with the object or decision the person came for.
2. Give each screen one obvious primary action.
3. Use plain language before system vocabulary.
4. Show boundaries where they affect a decision, not as constant chrome.
5. Disclose receipts, routes, and lower-level evidence progressively.
6. Never present declared, simulated, or local-only behavior as externally proven.

## Visual direction

The interface should be simple and visually strong. Spacious layouts, confident typography, and a small number of high-quality surfaces are preferable to dense explanation. Empty states should help someone begin real work.

## Product bar

A feature is not ready because its route exists. It should have a clear job, a calm first viewport, a useful empty state, an honest failure state, and a safe next move. Web, macOS, and iOS should agree on the underlying objects and authority model even when each platform uses native interaction patterns.
